## 修复一：保护旧成果

已知机制：`retry_run` 在新内容生成之前清理旧 HTML/PDF/bundle；随后文章、摘要、PDF 或 bundle 失败会损伤旧交付。缺失必需输入也可能发生在清理之后。

约束与方案：

- 新结果在独立工作区生成，成功后才发布；失败不能删除或修改此前可用 HTML、PDF、bundle、文章、章节及相应成功状态。
- 失败尝试应有可查诊断，不得把旧的成功结果误标失败；保留清晰的任务失败反馈。
- 成功产物必须来自同一版，不能把旧 PDF 混进新 HTML 的结果列表。
- 复用上游 metadata/transcript/chunks/media，不下载音频、不调用 Whisper。
- 兼容历史无文章的报告、bundle-only 重试、必需 PDF 与尽力 PDF 的原有区别。
- 由独立设计审查评估临时发布与独立 run 版本，选择能保持路径安全、错误恢复和外部调用语义清晰的实现；如需调整实现细节，在进度文档记录原因。

最小验证：文章失败、摘要失败、渲染失败、必需 PDF 失败、bundle 失败、输入缺失时，旧结果字节不变且仍可访问；成功后结果文件完整、返回路径正确；尽力 PDF 失败只能交付当次可用 HTML，不能冒用旧 PDF。

## 修复二：备用音频误删

已知机制：主候选失败留下 `last_error`，备用成功 return 后 finally 仍以旧错误删除 MP3。

方案：让清理依据当前候选是否成功；保留失败诊断用于所有候选均失败的情形。不放宽时长检查，不更换下载器。

最小验证：首候选时长错误/下载异常，次候选成功，函数返回成功且音频实际存在、内容来自成功候选并可被下一步读取；全失败仍抛正确错误且清理失败文件。

## 修复三：提前拦截超长视频

已知机制：超过 180 分钟的任务完成下载和转录后才在切块阶段拒绝；历史同一课程两次各白做约 8 分钟。

方案：拿到可信元数据时立即运行共享时长准入检查，在字幕获取、音频下载、Whisper 和 AI 之前拒绝；未知时长保留切块阶段兜底。不改变 `allow_long_video`、90–180 分钟确认与各入口既有授权语义。后段兜底沿用既有时长来源：有音频时用实测时长；仅字幕时用元数据，元数据缺失才用字幕末时刻。本轮不增加字幕时长真伪识别；独立 review 要求文档明确这一限制。

反馈：明确提示“视频超过 180 分钟，请在高级设置允许长视频后重新提交”，不要只给命令行错误；批量/飞书同样经过共享流水线门槛。本轮不扩展通用断点恢复引擎，也不对历史失败自动重新排队。

最小验证：180 分钟边界、超长允许/不允许、未知时长、90–180 分钟确认、强制 Whisper、字幕优先。超长未允许时昂贵函数调用为零，失败诊断完整；允许时正常进入后续流程。
